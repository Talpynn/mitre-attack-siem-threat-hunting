# Неделя 8 — полный комплект лабораторной работы

Начни с этого файла. `README.md` содержит план на английском и служит главной страницей этой папки на GitHub. Этот файл объясняет практику по-русски. Задание на скриншоте требует план; запуск стенда и доказательства расширяют работу до практической проверки.

Подготовлено: план, сопоставление ATT&CK, критерии проверки, четыре правила Wazuh, настройки журналов, безвредные скрипты, запросы поиска и бланк результатов. Доступ к твоему Windows/Wazuh не предоставлен: работа на стенде не запускалась, оповещения и скриншоты не получены. Проверки комплекта описаны в `VALIDATION.md`.

## 1 Что должно быть на стенде

Нужны три машины или роли в изолированной сети:

| Роль | Пример | Требования |
| --- | --- | --- |
| Windows target | 192.168.56.10 | Windows Pro/Enterprise/Server с RDP, Wazuh agent, Sysmon, curl.exe, Windows PowerShell 5.1 |
| Lab source and receiver | 192.168.56.20 | Python 3.9+, клиент RDP, доступ к Windows и TCP 8080 от Windows |
| Wazuh manager and dashboard | 192.168.56.30 | Администрирование конфигурации правил и доступ к оповещениям |

Адреса — предлагаемые, а не данные твоего репозитория. Если у тебя другие адреса, замени их в командах и `detection-rules/week8_rules.xml`. Для начального входа правило использует IP источника RDP; для передачи файла — IP получателя. В примере это одна машина, но роли можно разделить.

Создай отдельную временную учётную запись `labstudent` с уникальным паролем через настройки Windows. Разреши ей RDP только в учебной сети. Для создания задачи нужны соответствующие права: проще использовать временную административную учётную запись только на изолированной VM и открыть PowerShell с повышением в её RDP-сеансе. Не используй пароль основной учётной записи. Пароль в отчёт не включай. Windows Home не принимает RDP — для указанного правила нужна подходящая редакция либо другой сценарий входа и изменённое правило.

Сделай снимок VM. Запиши версии Windows/Wazuh/Sysmon/Python, имена машин и часовые пояса в `evidence/RESULTS.md`. Синхронизируй время. Скрипты записывают UTC; время на скриншотах может быть местным, для Алматы UTC+5.

## 2 Включить аудит и сбор журналов

На Windows открой `secpol.msc` → Advanced Audit Policy Configuration → System Audit Policies:

- Logon/Logoff → Audit Logon → Success.
- Object Access → Audit Other Object Access Events → Success.

На русской Windows названия переведены. Для доменной VM проверь, не переопределяет ли их GPO. До включения сохрани снимок VM или текущую политику: `auditpol /backup /file:C:\Windows\Temp\week8-audit-before.csv`. Проверь фактические параметры командой `auditpol /get /category:*`. Событие 4698 зависит от аудита, одного создания задачи недостаточно.

Скачай Sysmon только с официальной страницы Microsoft из `SOURCES.md`. На новой учебной VM распакуй архив, проверь схему `Sysmon64.exe -s`, затем из PowerShell администратора в папке Sysmon выполни:

```powershell
.\Sysmon64.exe -accepteula -i C:\week8-adversary-emulation\config\sysmon-lab.xml
```

Если Sysmon уже установлен, не удаляй его и не заменяй существующие правила вслепую. Сохрани исходный конфигурационный файл, добавь соответствующие ProcessCreate и NetworkConnect фильтры из примера и примени объединённую конфигурацию через `Sysmon64.exe -c <путь>`. Схема 4.90 в примере должна поддерживаться установленной версией. Event ID 3 нужно включать явно; по умолчанию сетевые события могут отсутствовать.

Проверь Event Viewer → Applications and Services Logs → Microsoft → Windows → Sysmon → Operational. В конфигурации агента Wazuh `C:\Program Files (x86)\ossec-agent\ossec.conf` добавь необходимые `localfile` из `config/windows-agent-snippet.xml` внутрь существующего `ossec_config`. Если Security уже собирается, сохрани существующий блок; не сужай общий сбор и не создавай дубликаты. Аналогично объедини Sysmon-блок с существующим. Сделай резервную копию конфигурации, затем перезапусти агент:

```powershell
Restart-Service WazuhSvc
```

Не добавляй в файл второй внешний `ossec_config` из примера. Входящий RDP разреши только от источника лаборатории. TCP 8080 на получателе разреши только от Windows VM. Не отключай межсетевой экран целиком.

## 3 Установить учебные правила Wazuh

На Wazuh manager проверь, что ID 100810–100813 свободны. Измени имя пользователя и адреса в XML под стенд. Сохрани файл как `/var/ossec/etc/rules/week8_rules.xml`; не перезаписывай штатные правила. Для Docker путь должен быть внутри контейнера manager или соответствующего постоянного тома. Проверяй конфигурацию именно того manager, куда подключён Windows agent.

Проверка и применение на обычной Linux-установке:

```bash
sudo /var/ossec/bin/wazuh-analysisd -t
sudo systemctl restart wazuh-manager
sudo systemctl status wazuh-manager
```

Перезапускай только после успешной проверки. При ошибке убери новый файл, верни резервную копию и проверь конфигурацию повторно. Для контейнерной установки команды перезапуска отличаются.

Сначала проверь каждое правило через `/var/ossec/bin/wazuh-logtest`, используя реальный исходный `full_log` соответствующего события из своей установки, а не внешний JSON оповещения с полями `agent`, `rule`, `data`. У Windows EventChannel есть особенности декодирования; если ручная вставка не воспроизводит декодер, окончательная проверка — событие через живой агент. Проверь реальные имена полей в декодированном событии: `win.eventdata.*`; в индексах они обычно доступны как `data.win.eventdata.*`. Не считай успешный разбор XML доказательством срабатывания правила.

Правила намеренно привязаны к лабораторным индикаторам. Вход `labstudent` с заданного IP сам по себе не доказывает компрометацию, а сетевое соединение не доказывает успешную передачу файла. Для последней нужны журнал получателя и совпадающий SHA256.

## 4 Запустить получатель

Скопируй папку комплекта на лабораторную машину. В терминале из корня комплекта:

```bash
python3 scripts/receiver.py --bind 192.168.56.20 --port 8080 --output evidence/received
```

Оставь терминал открытым. Скрипт принимает только точное содержимое заранее определённого учебного файла на `/upload`, сохраняет полученную копию и `receiver.jsonl` с UTC, IP отправителя, размером и SHA256. Обычная команда `python -m http.server` для этой работы не подходит: загрузку POST она не реализует.

## 5 Выполнить три этапа

**Initial Access.** С машины-источника подключись к Windows по RDP под `labstudent`. Это имитация использования уже известных учётных данных; их кража и подбор не выполняются. Запиши время входа. На Windows ожидается 4624 с `LogonType=10`. При наличии NLA могут быть и другие типы событий: для этого правила найди именно удалённый интерактивный вход. Если IP в событии отсутствует или отличается из-за шлюза/NAT, зафиксируй это и уточни правило по реальному полю.

**Persistence и Exfiltration.** Скопируй комплект на Windows, например в `C:\week8-adversary-emulation`. В RDP-сеансе тестовой учётной записи открой Windows PowerShell с необходимыми правами и выполни:

```powershell
Set-Location C:\week8-adversary-emulation
.\scripts\Invoke-LabStages.ps1 -ReceiverIP 192.168.56.20
```

Если политика запрещает неподписанные скрипты, на собственной изолированной VM можно временно установить `RemoteSigned` только для текущего процесса, предварительно проверив содержимое файлов:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Для файлов с отметкой загрузки из интернета после проверки используй `Unblock-File` только для двух PS1 из комплекта, если это требуется. Если политика задана организацией, не обходи её: согласуй разрешённый запуск. При ошибке создания задачи не меняй права системных папок; проверь права тестовой учётной записи.

Скрипт создаёт `Lab_Emulation_Test` с запуском от текущего пользователя при входе, вручную запускает её для первой проверки и передаёт только созданный `dummy-data.txt`. Задача пишет время в `task-marker.txt`, не открывает удалённый доступ и не запускает полученный из сети код. Следы и метаданные находятся в `%LOCALAPPDATA%\Week8-Lab\<run-id>`. Существующая задача с таким именем блокирует повторный запуск.

Для проверки закрепления запомни путь к `task-marker.txt`, **выйди из Windows-сеанса** и войди снова под той же учётной записью. Простое закрытие окна RDP не равно выходу. Дождись выполнения задачи: в маркере должна появиться новая строка UTC. Сохрани скриншот триггера, времени последнего запуска и маркера. Это подтверждает срабатывание при повторном входе; ручной запуск в скрипте подтверждает только работоспособность действия.

## 6 Собрать доказательства

Открой `HUNTING_QUERIES.md`, выставь интервал запуска в Wazuh и выполни запросы. Сохрани скриншоты и экспорт JSON оповещений в `evidence/`. Дополнительно на Windows можно сохранить исходные журналы из PowerShell администратора:

```powershell
wevtutil epl Security C:\Windows\Temp\week8-security.evtx /q:"*[System[(EventID=4624 or EventID=4698)]]"
wevtutil epl Microsoft-Windows-Sysmon/Operational C:\Windows\Temp\week8-sysmon.evtx /q:"*[System[(EventID=1 or EventID=3)]]"
```

Эти экспорты могут содержать другие события учебной VM; не публикуй их без проверки. Для отчёта достаточно выбранных событий периода запуска с сохранёнными техническими полями. Пароли, токены и посторонние данные в публичный GitHub не загружай.

Заполни `evidence/RESULTS.md`: время, agent ID, rule ID, результат, имена файлов и объяснение пропусков. Скопируй `run-metadata.json`, `receiver-response.json`, `task.xml`, `task-result.txt`, `task-marker.txt` и журнал получателя. Сравни хеши отправителя и получателя. Выполни контрольные проверки из `TEST_PLAN.md`. Отсутствие оповещения честно укажи как пробел наблюдаемости или обнаружения.

## 7 Удалить учебные изменения

После сохранения доказательств:

```powershell
.\scripts\Remove-LabTask.ps1 -WhatIf
.\scripts\Remove-LabTask.ps1
Get-ScheduledTask -TaskName Lab_Emulation_Test -ErrorAction SilentlyContinue
```

Последняя команда не должна вернуть задачу. Останови получатель `Ctrl+C`, отключи временную учётную запись и убери только добавленные для опыта разрешения firewall. Восстанови прежнюю политику аудита и конфигурации агента/Sysmon, если они менялись исключительно для лаборатории. После сохранения доказательств самый точный способ вернуть исходную VM — восстановить её снимок. Не удаляй Sysmon/Wazuh, если они уже использовались в проекте.
